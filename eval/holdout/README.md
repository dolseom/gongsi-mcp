# held-out 실발화 시험지

**고치는 데 쓰지 않는** 실무자 실제 질문 18문항. 개선 효과의 주 지표다 (b2a 는 결함에서 만든 문항이 섞여 순환 측정).

- 파일(로컬 전용, `.gitignore` — 제3자 게시글 원문이라 공개하지 않는다):
  `raw.jsonl`(수집 17건, 지식iN 16·블라인드 1) · `candidates.json`/`questions.json`(18문항: h001~h013·h016·h017 + 기존 코퍼스 카페 k010·k012·k036)
  · `golden-A.json`/`golden-B.json`(독립 작성, 원문 검증) · `golden.json`(두 골든 일치 결론만 core — Codex 확정) · `results/`
- 실행: `node scripts/eval-e2e.mjs --suite eval/holdout --concurrency 2 --repeat 2` → Codex 의미 판정(골든 golden.json 기준).
  판정 프롬프트 틀: 기준선 판정 결과 `results/eval-20260925-235518.codex-judge.md` 의 형식을 따른다.
- 규칙: 이 문항을 보고 **개별 문항에 맞춰** 도구를 고치지 않는다. 실패 유형에 대한 일반 해법만 넣고, 특정 문항을 근거로
  고쳤다면 그 문항은 빼고 새 문항으로 보충한다.
